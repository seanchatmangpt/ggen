## 4. Marketplace contract (~/ggen-marketplace)

- Registry manifest: `/Users/sac/ggen-marketplace/marketplace.toml` —
  `[marketplace] version = "v26.10.8"`, `[source_authority]`
  (seanchatmangpt/ggen-marketplace, canonical main, "mirrors are provenance
  only"), pinned `[ggen] version = "v26.8.11"` + per-platform asset sha256s,
  qualification worker/timeout config.
- **Registration = put the pack under `packs/<id>/` with a valid
  `pack.toml`.** "The permanent catalog is the set of admitted manifests under
  `packs/`" (README, "Pack profiles"); 332 pack dirs measured. No separate
  index to edit — `python3 scripts/marketplace.py catalog` is the
  deterministic projection, re-derivable at any time.
- `pack.toml` required sections: `[pack]` (name, SemVer, non-empty
  description) and `[capabilities]` with
  `provides`/`requires`/`types` as URN arrays; **self-IRI law**: `provides`
  must contain `urn:ggen:pack:<pack-id>` exactly, globally unique
  (`deny_unknown_fields` on the table; corpus court
  `tests/capability_corpus_test.rs` in ggen-marketplace).
- Pack profiles: projection / semantic / project. Every profile requires
  `pack.toml` + ≥1 Turtle source at pack root or under `ontology/`.
- Consumer contract: reference the pack in consumer `ggen.toml`:
  ```toml
  [packs]
  my-pack = { path = "../ggen-marketplace/packs/my-pack" }
  ```
  then `ggen sync run` in the consumer. Verification: `python3
  scripts/marketplace.py validate|catalog|fingerprint`, plus
  `bash scripts/admit-config.sh` / `scripts/qualify-marketplace.sh`.
- Full contract doc: `/Users/sac/ggen-marketplace/README.md`.

## 6. Command sequence to generate a new pack from an ontology

```bash
# 0. (once) ggen binary: ~/.local/bin/ggen, or
cargo build -p ggen-cli-lib --bin ggen   # in /Users/sac/ggen

# 1. Project + pack scaffold
mkdir my-proj && cd my-proj
ggen init --path .                         # scaffold + ggen.toml + schema/domain.ttl
ggen init-self                             # materialize packs/ggen-self-pack/
ggen pack new my-pack --description "…" --namespace http://example.org/my#

# 2. Ontology: edit schema/domain.ttl (or ontology.ttl) — Turtle
# 3. Rules: [[generation.rules]] in ggen.toml:
#      query  (SPARQL SELECT, MUST end in ORDER BY under default strict_mode)
#      template = { file = "templates/x.tmpl" }
#      output_file, mode = "Overwrite"
# 4. Template: Tera body + YAML frontmatter (to: / for_each: / sparql:)
# 5. Generate + verify determinism
ggen sync run --dry-run     # render without write
ggen sync run               # writes + JSON receipt (BLAKE3 hashes, graph_hash_hex)
ggen receipt verify         # replay-provenance chain

# 6. Marketplace registration
#    copy/move the pack to ~/ggen-marketplace/packs/<id>/ with pack.toml
#    ([pack] + [capabilities] incl. self-IRI urn:ggen:pack:<id>, ≥1 .ttl)
python3 scripts/marketplace.py validate
python3 scripts/marketplace.py catalog
```

Key gotchas (all observed, not inferred): (a) scaffold queries ship failing
strict_mode ORDER-BY validation — add ORDER BY or set `strict_mode = false`
in `[validation]`; (b) `ggen pack new` requires `ggen init-self` first;
(c) templates are Tera + YAML frontmatter, not handlebars; (d) sync receipts
carry BLAKE3 input hashes + graph_hash_hex — determinism is a validated
property, not a promise.
