# ERRC: the pack-testing pattern

Blue Ocean Strategy's Eliminate–Reduce–Raise–Create grid, applied to how
this repo tests `packs/*` — grounded in `scripts/ci/guard-pack-e2e-coverage.sh`'s
own real output (81 packs total; 15 have real testable surface — `gates/*.rq`
or `templates/*.tmpl` — and no e2e coverage anywhere, checked by grepping
every file under `crates/ggen-engine/tests/` for the pack's own directory-name
string, not by guessing test filenames), not a generic template. That number
has moved twice already, each time downward for a real reason, not by
adjustment: an initial hand survey said 67 (it only looked at files named
`*_pack_e2e.rs`, missing real coverage some packs get from broader
multi-pack tests like `composed_packs_e2e.rs` — `tcps-release-pack`, 85
templates, the single largest pack, turned out to already be covered
there); the corrected gate script then found 22; running its own
`pat:ExistingPackStub` generator against the cheapest uncovered packs
closed 7 more for real (5 then 2), landing at 15 — with 5 of the remaining
15 already attempted and found to need real per-pack domain-ontology work
(their gates correctly refuse an empty consumer ontology) or a genuine
non-determinism bug fix, not more stub-generation. Living document:
regenerate it via `ggen sync` rather than hand-editing, the same as every
other page here.

## Eliminate

- **Per-file scaffold duplication.** Before `crates/ggen-engine/tests/
  support/mod.rs` existed, `copy_tree`/`scaffold`/`read` were reimplemented,
  byte-for-byte identically, in 9 separate `*_pack_e2e.rs` files. All 9 now
  import the shared versions; ~150 lines of duplicate boilerplate removed,
  zero behavior change (verified: every migrated file's tests pass
  identically before and after).
- **"No test at all" as the silent default for a new pack.** Before this
  pack existed, authoring a new pack meant either copying an existing
  `*_pack_e2e.rs` by hand or, more often, shipping with zero e2e coverage —
  which is how 15 of 81 packs remain untested today. `pack-authoring-pack`
  always emits a stub test alongside a new pack's scaffold; skipping
  coverage now takes an active choice, not an absent one.

## Reduce

- **Idempotency + gate-sabotage boilerplate**, from ~20-40 hand-written
  lines per pack to two function calls (`assert_idempotent`,
  `assert_gate_refuses`) — already true for every migrated file.
- **Bespoke scaffold-shape reinvention.** Two real variants surfaced by
  reading all 7 remaining files, not invented up front:
  `scaffold_pack_with_ontology` (pre-populated consumer ontology — used by
  `tai_rebuild_pack_e2e.rs`) and `read_json` (JSON-parsing read — same
  file). Genuinely different shapes (nested pack paths, `[law] reflexive =
  true`, `extra_ontologies`, declarative-rules `[[generation.rules]]`,
  `CliHarness` subprocess vs. in-process `sync()`) were deliberately left
  local rather than forced through one wrapper — a wrapper that silently
  changes what is being tested is worse than the duplication it replaces.

## Raise

- **A visible, enforced coverage floor.** `scripts/ci/guard-pack-e2e-coverage.sh`
  is now a real ratchet, not just a report: it hard-fails `pre-commit` the
  moment the real uncovered count exceeds the checked-in baseline
  (`.specify/pack-e2e-coverage-baseline.txt`, currently `15`) — a pack
  losing coverage or a new pack shipping real testable surface with none
  is now a build break, not a silent regression. It does not demand the
  current 15 close first (several are legitimately blocked on real
  per-pack domain work this pattern cannot manufacture) — proven as a real
  gate, not asserted: lowering the baseline file by one and re-running the
  script was checked to actually fail before the correct value was
  restored.
- **Assertion quality as the norm, not the exception.** Every migrated and
  generated test asserts real content substrings (a `#[test]` that only
  checks `sync()` returned `Ok` is not yet a Chicago-TDD proof, per
  `how-to-write-a-chicago-e2e-test.md`) — the `chicago-tdd-tools-pack`
  "proof of the generated proof" idiom generalized to every pack, not just
  the one pack that originated it.

## Create

- **The coverage-tracking ratchet gate** (above) — makes the gap a number
  that can only shrink on purpose, self-corrects when the measurement
  itself improves (67→22, see above), and now actually enforces the floor
  instead of only reporting it (22→15, closed by the stub generator below).
- **Ranked, real stub generation** for the highest-surface uncovered packs
  (`pat:ExistingPackStub` + its template) — closes a bounded, verified
  subset per pass rather than claiming the full remaining count in one,
  which would trade real coverage for the appearance of it.
- **This document itself**, regenerated by the same `ggen sync` that
  produces every other page here — an ERRC analysis that goes stale the
  moment the inventory changes is worse than no analysis; this one is
  re-derivable, not a one-time memo.
