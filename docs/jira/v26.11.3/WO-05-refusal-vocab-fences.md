## Task

### 1. Author the missing ggen.toml rule (closes gap a)

Make the module genuinely ggen-generated. Gate is behavior, not literal syntax — adapt to the
actual manifest schema, mirroring how the engine-side module
`crates/ggen-engine/src/generated/refusals.rs` is rule-bound if a binding exists there:

- **Manifest rule** (e.g. `typed_boundary_refusal_abb_sbb`): binds
  - SPARQL `SELECT` over `ontologies/shapes/boundary-refusal.shacl.ttl` returning the `br:code`
    individual rows (code, prefix, description, producer surface) in deterministic order
    (sort by code; keep it that way),
  - template `templates/typed-boundary-refusal-rust.tera` (parameterized only by registry rows;
    hand-edits to the module never land again), output path
    `crates/ggen-abb-sbb/src/generated/refusals.rs`.
- **Determinism + freeze checksum**: run the rule twice, assert byte-identical output, and pin
  the frozen checksum of the committed module (a `# CHECKSUM=` line in the manifest rule or a
  sidecar file, e.g. `src/generated/refusals.rs.checksum`), so CI can check "rendered ==
  committed" without re-rendering. A drift between rendered and committed is a fail-closed CI
  refusal, never an auto-overwrite.
- **Grep gate**: `grep -rn "typed-boundary-refusal-rust.tera" ggen.toml crates/ggen-abb-sbb/ggen.toml 2>/dev/null` exits 0 with a rule binding; likewise the `.shacl.ttl` path.

### 2. Two crosswalk courts (closes gap b)

New `crates/ggen-abb-sbb/tests/refusal_crosswalk_courts.rs` (split into two files if house style
prefers, mirroring `crates/ggen-engine/tests/refusal_crosswalk_court.rs`).

- **registry↔generated court**: every SHACL individual (`br:code` in
  `ontologies/shapes/boundary-refusal.shacl.ttl`, parsed from the real file) has a `Code` variant
  + `wire()` arm in the abb-sbb generated module, and vice versa — bijection on the 11 registry
  codes. The 3 `E-PARSE-*` codes are string-surface (no registry individual today); the court
  must state their standing explicitly (either they gain registry individuals in this WO or they
  carry registered-divergence rows — decide, do not skip).
- **kernel↔registry court**: for each of the 27 kernel `Refusal` variants
  (`crates/ggen-abb-sbb/src/lib.rs:222`): exactly one of
  1. **registry surface** — a mapped `br:code` individual (today only `Refusal::StaleLease` →
     `REFUSED_STALE_LEASE` is documented), or
  2. **registered divergence row** — a table in the court file with per-row: variant name, reason
     kernel-local, close condition.
  Court fails on: a variant with neither (unmapped), a divergence row whose variant no longer
  exists (stale row — degrade to FAIL, never silent pass), or a variant deleted while its row
  stands (see acceptance 4).

Chicago court: real files, real SHACL parse, real enum source parse; no mocks.

### 3. Census-guard extension (closes gap c)

`scripts/ci/guard_wire_code_census.py` already lists the abb-sbb enum in `DEFAULT_ENUMS`. The
lane's work here:

- **Anti-vacuity verification**: the guard passes today; removing a code from the abb-sbb module
  flips it to exit 1 (prove the gate can refuse — record exit codes).
- **Kernel-variant census**: extend the guard (or a sibling guard in the same file) to census the
  kernel `Refusal` variant names against the kernel↔registry court's map+divergence table, so the
  guard and the court agree on the kernel inventory. Parse format: the `#[error("...")]` literals
  in `crates/ggen-abb-sbb/src/lib.rs` (extend `REGISTRY_CODE_RE`-style parsing; pin the landed
  format).
- If task 2 adds new `br:code` individuals, re-run the guard; extend `REGISTRY_CODE_RE` only if
  the landed format changes.

### 4. Divergence-row discipline

Each kernel-local divergence row carries a close condition and a falsifier: deleting the kernel
variant fails the court (stale row), promoting a variant to a registry surface moves the row out
of the divergence table and into the court's map. Rows are append-only within this WO; a row
removed must be justified by a promotion receipt.
