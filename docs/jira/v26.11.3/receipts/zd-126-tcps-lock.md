## Root cause 1 — the lock was simply never tracked

Consumer contract (`tests/product_evidence/manifest.rs:validate_ggen_lock`) expects the

## Root cause 2 — why the recipe command alone could not regenerate it

`ggen sync run --skip-ea-admission` (the XD-15 recipe) failed on this branch, three
deep, each refusal pre-write:

1. **Committed state was lease-deadlocked.** HEAD `.ggen-v2/receipt-log.jsonl` tail is
   generation 1 (next run's generation = 2), but HEAD lease slot
   `88c212d8…` (`receipts/EVIDENCE_SNAPSHOT.md`) holds baseline 2 — every run refuses
   `[FM-WRITE-012] REFUSED_STALE_LEASE` before it can advance the log. Refusals do not
   append, so the recipe's own remediation ("re-run sync") is unreachable. Repair used
   the code-documented remediation (`write.rs` read_lease_baseline doc: "repair or
   remove the slot after reviewing the target's owning generation"): removed the slot
   (missing slot = baseline 0, admits once, then re-records).
2. **Committed docs byte-stale by one trailing newline.** Pack templates end `}}\n`
   and Tera output is taken verbatim (`Tera::default()`, autoescape off) — the
   template's trailing newline leaks into every rendered artifact (probe: 12-byte body
   renders 13 bytes, `/tmp/abi-probe`). All committed `infra/**/*.md` were trimmed
   copies → `[FM-WRITE-005]` refusing silent clobber before `ggen.lock` was reached in
   write order. Each refusing clobber run appends a Halted receipt, which then trips
   `ggen-verify-pack` gate `040_latest_andon_green.rq` on the next run; the log tail
   was restored to HEAD between iterations to break that spiral. Fix: let the
   generator re-land the artifacts (rm stale copy → sync writes fresh), 9 files, each
   `+1` newline.
