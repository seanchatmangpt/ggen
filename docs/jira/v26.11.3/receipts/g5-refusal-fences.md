## Rule shape (why VALUES + ORDER BY)

The rule's inline SELECT joins `br:BoundaryRefusal` individuals (?wire from
br:code) to an inline VALUES table (?wire, ?variant, ?ctor). Variants and
ctors are CURATED, not derivable: registry variants strip the surface prefix
(E-ENVELOPE-UNDECLARED -> EnvelopeUndeclared; FD-UNDECLARED_INPUT_DIALECT ->
UndeclaredInputDialect) and the graph carries no variant names. A registry
code missing from VALUES would drop out of the render silently; the
VALUES<->TTL arm of the crosswalk court makes that loud.
`ORDER BY ?wire` (determinism law): alphabetical wire order, witnessed
byte-identical across two consecutive `ggen sync run` invocations.
