## Audit findings (each verified live this session)

**A1. Manifest schema shape — declarative-rules (schema 1).** 12 enabled
`[[generation.rules]]`; project.version present (legal on schema 1, FM-CONFIG-101
on schema 2). No `[packs]`. Dry-run validated: exit 0 (see Gates). Note: the
manifest is authored repo-root-relative (its own zod-schemas comment documents

`cp ggen/ggen.toml ggen.toml && ggen sync run && rm ggen.toml`. All further

**A2. GROUP_CONCAT — one live use, migrated off.**
`ggen/queries/extract-source-modules.rq` line 11 used
`GROUP_CONCAT(DISTINCT ?law; SEPARATOR=",") AS ?laws`. Skill: GROUP_CONCAT is
broken on 26.10.11 in ALL forms (column silently drops). Verified dead plumbing:
ontology carries only the property declaration
(`wasm4pm-compat.ttl:141`), zero instance data. Committed audit outputs prove
the empty branch was the only branch ever taken (every `audits/*.sh` renders
"INFO no laws declared"). Fix: aggregate removed from query; GROUP BY dropped;
`audit-script.tera` CHECK 4 replaced with the unconditional INFO line
(output-preserving — the non-empty branch was unreachable). Header docs updated
in both files.

**A3. Fill-forward trap — live corruption found and fixed at source.**
Six queries fed templates from partially-bound OPTIONAL columns:
`extract-witnesses-full.rq` + 5 category queries (witnessYear / witnessFamily /
description), `extract-all-witness-keys.rq` (family/year),
`extract-zod-schemas.rq` (fieldType + 5 flag columns), `extract-breed-witnesses.rq`
(year). Live witness: committed `src/witnesses_ai_llm.rs` had `None` where the
post-render file showed `Some(1994)` on rows whose TTL has NO witnessYear —
unbound `witnessYear` filled forward from a prior row. Silent wrong values, no
error. Fix: every template-consumed OPTIONAL column is now re-bound with
`BIND(COALESCE(?raw, <default>))` so every row binds every column explicitly.
Post-fix diff vs committed shows whitespace-only deltas — fill-forward
corruption eliminated. zod `.optional()`→`.default([])` drift was NOT fill-forward:
verified as legitimate source evolution (TTL carries `zod:isDefaulted true` on
events/objects/attributes/relationships, zod-types.ttl:191-197, 232-233, 525-526,
541-542); committed output was stale → regenerated per GGM-SRC-002.

**A4. Typed-literal equality traps — audited, none found.** The only `==`
comparisons on possibly-optional columns were `law_list == ""` (string compare
of a COALESCE'd/empty default — now removed with A2) and the zod template's
`row.fieldType == "string"` etc. — string-vs-string, safe (fieldType is now
COALESCE-bound to "" on unbound rows; unmodeled types render z.any() stub).
`{% if row.isOptional %}`-style truthiness checks are not `==` comparisons and
are safe post-COALESCE. No `== "1"` vs `== 1` traps found in any enabled
template.

**A5. ORDER BY — PASS.** All 13 enabled-rule queries (12 rules; two audit rules
share select-audit-specs.rq) carry ORDER BY; no E0013 risk under strict_mode.
