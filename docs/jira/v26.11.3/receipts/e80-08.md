## Subject

The execution loop port deferred by X1's port-coverage table:
`run(orders, ledger_path, authority_graph, opts)` drives
**frontier → authority → plan → receipt → reconcile** to fixed point over a
REAL file ledger, composing the landed modules via pub APIs only:

- frontier hop reads the REAL ledger via `ledger::fetch` (tampered/undecodable
  ledger refuses typed `ledger_refused` / `R_missing_replay` before anything
  runs) and selects via `frontier::frontier`.
- authority hop re-derives the typed origin law per eligible candidate via
  `authority::AuthorityIndex::build_pinned(...).resolve(...)` — frontier's
  map gate PLUS the digest/pin law.
- plan hop: projections + required_courts ARE the admitted plan
  (`ExecutionPlan`); the consumer (fabric/backend) executes it — sjira's
  contract is the ADMITTED plan + receipt, per the igniter's
  "local backend caps at partial_alive" law.
- receipt hop: one blake3 `TransitionJournal` `Decision::Admitted` transition
  per execution (authority `NONE` — never creates authority).
- reconcile hop: `ledger::append` LAST write stamps seq/epoch/event_digest;
  idempotent replay (`AlreadyRecorded` is not a second execution).
