## Design

- `FileEdit::capture(path, after_bytes)` records the real before-image (or
  absence, committed as the empty-image SHA-256) plus SHA-256 commitments
  over both images.
- `FileEdit::invert()` / `TransactionalEdit::invert()` produce the exact
  inverse delta set (before/after swapped, reverse edit order, deletion
  encoded as empty after-image). The inverse keeps the original chain
  position — it is a derived journal, not a new link.
- `apply` verifies each target against `before_sha256` before writing;
  `rollback` verifies ALL targets against `after_sha256` FIRST (a mid-set
  divergence cannot leave a half-rolled-back state), then restores in
  reverse order. Divergence = typed `[FM-WRITE-02n]` refusal, never silent.
- Writes are crash-safe: temp file → fsync → rename.
- `Journal` is an append-only JSONL ledger with a BLAKE3 prev-hash chain;
  `open` refuses corrupt lines (`-023`), chain breaks (`-024`), hash
  mismatches (`-025`), stale appends (`-026`); `recover` classifies each
  edit against its commitments and rolls forward to a consistent state,
  refusing files that match neither commitment (`-027`).
- Error band `[FM-WRITE-020..027]` is disjoint from write.rs's
  `[FM-WRITE-001..012]`. write.rs was NOT modified — this module CONSUMES
  the byte images a planned write produces (capture before apply).
