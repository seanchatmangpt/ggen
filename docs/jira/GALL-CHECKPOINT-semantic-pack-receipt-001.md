## Why this checkpoint exists

`ggen` already emits the RFC-GPACK portable receipt envelope and a SHA-256 PackDigest while preserving the legacy BLAKE3 chain receipt. The remaining release-critical gap is that the portable envelope currently reports replay as `UNKNOWN`: source presence and a generated receipt are not yet evidence that the exact admitted semantic subject can be replayed deterministically and re-bound to the same artifact identity.

This checkpoint converts the existing receipt surface into an executable GALL seal.

## Preserve

- RDF / pack inputs remain canonical semantic source.
- Generated artifacts remain projections; no generated product file becomes authority.
- The legacy `.ggen-v2/receipt.json` BLAKE3 chain remains byte-compatible unless a separate compatibility RFC admits a change.
- `.ggen-v2/receipt-portable.json` remains a reporting envelope, not a grant.
- `ggen` emits process evidence; it does not absorb process-mining/conformance analysis owned elsewhere.
- Dry-run remains consequence-free.

## Required transition

`Pack source -> admission -> canonical PackDigest -> deterministic manufacture -> consequences[] -> portable receipt -> replay -> standing`

Current main additionally admits dependency-scoped semantic resolution. The checkpoint closes only when the replay observation is bound to the same exact pack, engine, graph, declared dependency closure, output bytes, and toolchain subject; ambient/global providers cannot be smuggled into replay identity.

## Required implementation

1. Add a repository-native replay court for the portable receipt envelope.
2. Replay from a clean output state; do not reuse generated bytes as the oracle.
3. Recompute the RFC-GPACK SHA-256 PackDigest independently from the emitted envelope field.
4. Recompute canonical graph identity, declared dependency-closure identities/digests, and generated consequence SHA-256 values.
5. Require the replayed consequence set to match the receipted consequence set exactly: path, operation, content digest, and cardinality.
6. Preserve typed admission refusals and prove a refused pack cannot manufacture a replay PASS.
7. Record exact engine/toolchain identity and dependency closure sufficient for reconstruction.
8. Promote `replay.status` to `PASS` only from observed execution; otherwise keep `UNKNOWN` or a typed failure state.

## Falsifiers

The checkpoint fails if any of the following survives:

- change one admitted pack byte without changing PackDigest;
- change canonical graph content without changing graph identity;
- change declared dependency scope/version/digest while preserving the old replay identity;
- mutate one generated consequence after the first run and still report replay PASS;
- delete/add/reorder a consequence in a way that changes semantics while replay still passes;
- emit replay PASS for a pack refused by admission;
- reuse an old receipt against a different exact source revision;
- allow dry-run to manufacture durable checkpoint standing;
- compute the replay expectation from the already-generated output being tested.

### Actual remaining closure

The load-bearing replay field is still explicitly hard-coded to `"UNKNOWN"`:

`PortableReplay { status: "UNKNOWN" }`.

Therefore GALL-001 is no longer a generic "build a portable receipt" ticket. The narrow missing subject is a real clean-state replay court that independently reconstructs the same admitted subject and consequence set.

The court must:

1. start from a clean output state rather than the first run's generated bytes;
2. independently recompute PackDigest, graph identity, dependency closure, and consequence set;
3. compare exact path + operation + digest + cardinality;
4. bind exact toolchain/environment identity sufficient for reconstruction;
5. prove mutation/refusal witnesses;
6. change replay standing only from observed execution.

### Multi-pack identity falsifier

The current portable envelope selects `packs.first()` as its subject and derives dependency closure from that pack. A sync may contain other unrelated top-level packs. GALL-001 MUST refuse to imply that a first-pack receipt identifies an unrelated multi-pack composition.

Close this either by a receipt-per-subject model or by an explicit composition identity whose members are all bound. Do not infer composition identity from iteration order.

### Weaver consequence rule

A generated semconv registry, Weaver template input/output, Rego support artifact, or telemetry constant needs no parallel receipt architecture. If ggen manufactured the bytes, the existing consequence list is the natural binding surface. The missing work is replay plus exact specialist-producer identity where reconstruction depends on an external Weaver binary.
