# Mechanical Gates Spec — v26.11.4 Closure

Three failure classes witnessed repeatedly this session, each spec'd as an
implementable gate (data shapes, hooks, commands) — not prose. Each section:
data shape, enforcement point, effort, and the witnessed instance it would
have prevented. These feed v26.11.5 SEED rows.

## Gate 1 — Lane-ID / Lease Registry

### Problem (witnessed instances)

- **D25-first-run vs D32 collision**: lane IDs existed only in coordinator
  context. D32's commit swept D25's staged first-run deletions — two lanes
  wrote one commit with no machine-readable boundary.
- **C6's U4 riding a11f072b**: attribution split across SHAs; the U4 receipt
  referenced work physically committed under a different lane's SHA.

### Data shape — `docs/jira/<milestone>/_LANES.md` is prose; the registry is JSON

`docs/jira/v26.11.4/lane-registry.json` (per-milestone, coordinator-minted
at wave open, single writer = coordinator):

```json
{
  "milestone": "v26.11.4",
  "repo": "ggen",
  "lanes": [
    {
      "lane_id": "D25",
      "repo": "ggen",
      "owned_paths": ["crates/ggen-cli/verbs/**"],
      "status": "leased | done | released | blocked",
      "receipts": ["docs/jira/v26.11.4/receipts/d25-first-run.md"],
      "lease_expires": "2026-11-04T20:00Z"
    }
  ]
}
```

Fields: `lane_id` (session-stable string, never inferred from cwd or
prompt), `repo` (absolute canonical checkout identity), `owned_paths`
(gitignore-style globs, disjoint across live lanes — enforced at mint),
`status` (enum), `receipts[]` (paths this lane has produced), `lease_expires`
(stale leases refuse at pre-commit, not silently).

### Enforcement point — pre-commit hook (refuse, not warn)

`scripts/hooks/lane-lease-check` wired as `.git/hooks/pre-commit`
(or `core.hooksPath`):

```
1. LANE_ID from env GGEN_LANE_ID (empty -> exit 1: "no lane lease in
   environment; commits are coordinator-only").
2. Committed files: `git diff --cached --name-only`.
3. For each file, match against the lane's owned_paths globs.
4. Any file outside owned_paths -> exit 1 with the offending path and
   the owning lane's ID (from the registry), so the fix is mechanical.
5. Stale lease (now > lease_expires, status != released) -> exit 1.
6. Coordinator commits: GGEN_LANE_ID=COORD bypasses path check but
   still requires the registry to list every staged path under some
   lane (audits orphan files).
```

### Coordinator-side slot map

`docs/jira/v26.11.4/_slot-map.md`, regenerated by the coordinator at every
dispatch (`scripts/lane_slot_map.sh lane-registry.json`):

| slot | lane | owned paths | status | last receipt |
|---|---|---|---|---|
| 1 | D25 | `crates/ggen-cli/verbs/**` | released | d25-first-run.md |

Regeneration is a read-only projection of the registry — hand edits to the
slot map are prohibited (projection-not-copy, same law as the doctrine hook).

### Effort

S-M: hook script (~60 lines bash) + registry schema + slot-map script.

### Would have prevented

D25/D32 staged-deletion sweep; C6/U4 attribution split across a11f072b.
Also mechanically enforces the same-checkout-fanout law 3 ("agents never run
git state commands — coordinator owns transitions"): the hook is the
mechanism the law lacked.

## Gate 2 — Shared-Index Disclosure Automation

### Problem (witnessed instances)

- **D32 / D57 / D83 class**: three lanes had staged work swept into
  neighbors' commits. Root cause: shared `git index` — a lane's
  `git add` stages its own files plus whatever a concurrent lane already
  staged; `git commit` commits the whole index.

### Detection — staged-vs-mine diff at commit time

Second pre-commit check (same hook family as Gate 1, sibling script
`scripts/hooks/index-disclosure`):

```
1. MINE  = files matching $GGEN_LANE_ID's owned_paths (registry lookup).
2. STAGED = `git diff --cached --name-only`.
3. FOREIGN = STAGED - MINE.
4. FOREIGN empty  -> exit 0, silent.
5. FOREIGN non-empty -> exit 1 listing:
     - each foreign path + its owning lane ID
     - the fix: `git restore --staged <paths>` (unstage, never commit)
       OR `GGEN_LANE_DISCLOSE=<lane-id>` to explicitly adopt (writes the
       attribution footer below and proceeds).
```

### Attribution footer automation

When `GGEN_LANE_DISCLOSE` is set, a `prepare-commit-msg` hook appends to the
message file:

```
Index-disclosure: foreign paths committed under <lane> lease by <lane>:
  <path1> (owner: D57)
  <path2> (owner: D83)
```

This makes the sweep visible in `git log` — the a11f072b-style attribution
split becomes greppable instead of archaeology.

### Enforcement point

pre-commit hook (refuse by default, disclose-to-adopt) + prepare-commit-msg
hook (footer). Both read the same `lane-registry.json` as Gate 1 — one
registry, two consumers.

### Effort

S: ~40 lines bash for the diff check + ~15 for the footer hook.

### Would have prevented

The D32/D57/D83 swept-commit class entirely: at minimum, each sweep would
have required an explicit per-path disclose, landing as a greppable
attribution footer instead of silent misattribution. Also satisfies the
compile-freeze-disclosure law (same-checkout-fanout addition 6) mechanically.

## Gate 3 — Receipt-Lint Standing Vocabulary

### Problem (witnessed instances)

- **E-y2 / P-p census finding**: ~60 receipts across the fleet failed the
  standing-line census — not because status was missing, but because the
  vocabulary drifts: `Standing:` / `Status:` / `verdict:` / `Exit-code:`
  all carry the same bit, and the census regex matched only one.

### Accepted synonym vocabulary

Canonical field: `Standing:`. Accepted synonyms (case-insensitive, must be
a line-start key):

```
Standing | Status | verdict | Result | Exit-code | Exit code | Gate
```

Accepted standing values (the ALIVE vocabulary, case-sensitive as written):

```
ALIVE | PARTIAL_ALIVE | PARTIAL | BLOCKED | REFUSED | UNSUPPORTED |
UNKNOWN | VERIFIED | DECIDED | OPEN | CLOSED | CLOSED-SIMULATED |
FAIL-HONEST | BUILD_BROKEN | CONFORMANT | PASS | FAIL
```

Backtick-wrapped and parenthesized-suffix forms are stripped before match
(`VERIFIED(9/9)` parses as `VERIFIED` with annotation `9/9`).

### Lint spec — `scripts/receipt_lint.py`

```
Input:  one or more receipt files (or a receipts dir).
Per file:
  1. Find a line matching ^#?\s*(Standing|Status|verdict|Result|
     Exit-code|Exit code|Gate)\s*[:=]\s*(.+)$ (case-insensitive key).
  2. Strip backticks/parens from the value; take token[0] as standing.
  3. If no key line -> FAIL: "no parseable standing line".
  4. If value not in vocabulary -> FAIL with the accepted list.
  5. Emit receipt: file, matched key, parsed standing, annotation.
Exit 1 if any FAIL. --backfill mode: for files missing a key line but
containing an unambiguous value token in the first 5 lines, emit the
inserted `Standing: <value>` line as a diff (never writes files).
```

### Enforcement point

- CI job (per-repo, `just lint-receipts`): exit-1 census over
  `docs/jira/*/receipts/**` + `receipts/**`.
- Census extension so it never re-flags: the census consumes the lint's
  parsed output (file -> standing map) instead of its own regex. Once a
  file parses, it is marked in `receipt-standing-map.json`; the census
  re-flags only files whose standing line changed since last map write
  (mtime+hash), never files that already parse.

### Backfill (D108, already executed)

D108 ran the lint in `--backfill` mode across the ~60 flagged receipts and
inserted canonical `Standing:` lines. The standing-map hash pins that state;
the census compares against the map, so the backfilled files never re-flag.

### Effort

S (lint script + vocabulary) + S (census extension) — this is S-10 in
next-wave-seeds.md, confirmed S with the vocabulary enumerated.

### Would have prevented

The ~60-receipt unparseable-standing census failure (E-y2/P-p finding);
and the census re-flag churn that made the failure look like missing
status rather than vocabulary drift.
