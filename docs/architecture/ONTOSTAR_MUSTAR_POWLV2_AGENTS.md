# GBB-002: OntoStar, POWL v2, MuStar, and GPT-5.6 Agents

## Preserve

OntoStar, POWL v2, and MuStar already represent different authority layers and must not be flattened into a generic chat-agent loop.

- OntoStar is the ontology observation and admission layer.
- POWL v2 is the executable process grammar and partial-order planning layer.
- MuStar is the semantic-to-kinetic compiler.
- Agents and models are candidate generators.
- BRCE is the only actuation path.

The Speedrun Talent Network Building Block from GBB-001 remains an independently verified substrate rather than becoming hand-written tool code inside an agent framework.

## Fence

This checkpoint manufactures a new pack and generated standalone Rust consumer. It does not modify:

- `crates/ggen-architecture`;
- the Speedrun source ontology or templates;
- upstream `wasm4pm` process-mining mathematics;
- any provider SDK;
- any candidate consent record.

The pack uses PROV-O for agents, entities, and plans; Schema.org for software/model products; ODRL for the candidate-only prohibition; DCTERMS and SKOS for identifiers and definitions. Local `af:*` terms are a bounded integration profile. No `oo:*` vocabulary is first-authored.

```text
admitted source digest
```

## Framework contracts

### OntoStar

OntoStar accepts claims only when every subject, predicate, object, and evidence digest is present. Evidence identities must be BLAKE3 URNs. It performs no local process-mining mathematics and cannot actuate.

### POWL v2

The generated grammar supports:

- activity;
- sequence;
- exclusive-choice candidate structure;
- parallel candidate structure;
- explicit partial order.

Admission normalizes the candidate to a precedence graph, refuses duplicate activities, unknown references, self-dependencies, empty composites, and cycles, then seals a deterministic plan digest.

### MuStar

MuStar requires the Luna–Terra–Sol model-intent triad and compiles each admitted POWL activity into a Motion Packet. Every packet carries:

- its admitted plan digest;
- deterministic identity;
- predecessor closure;
- model-intent identities;
- BRCE as broker;
- candidate-only and no-execution-authority flags;
- required consequence evidence dimensions: substrate, state, process log, telemetry, and causality.

### GPT-5.6 capability routing

The ontology assigns Luna to bounded extraction/routing, Terra to balanced workflow-candidate planning, and Sol to frontier adversarial verification/synthesis. These are capability tiers, not hard-coded network clients. Provider execution remains external and `UNKNOWN` until receipted.

## Exclusions

- ReAct-style free-form actuation;
- model output treated as truth or authority;
- direct HTTP, process, filesystem, or provider-SDK execution;
- Python agent framework authority above the Rust admission boundary;
- private replacement process-mining mathematics;
- application submission;
- stealth-company unmasking;
- candidate action without explicit action-matched consent.

## Falsifiers

The generated witness rail refuses:

1. an OntoStar claim without a BLAKE3 evidence identity;
2. a cyclic POWL partial order;
3. MuStar compilation without exactly three admitted model-intent identities;
4. a Speedrun candidate action without consent;
5. any framework or model profile that declares execution authority;
6. any generated source containing direct network actuators.

A positive end-to-end fixture manufactures the same bundle twice, proves byte-level semantic equality, routes Luna → Terra → Sol, compiles three ordered Motion Packets, manufactures a read intent, refuses unconsented interest, and admits the same interest with role-scoped consent.
