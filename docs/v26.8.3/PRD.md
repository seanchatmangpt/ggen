# Product Requirements Document — ggen v26.8.3

## Claims Reconciliation

This document defines the v26.8.3 target for the **Repository Manufacturing Kernel**. The current exact baseline is `8351af4c5bbbf60bd99ab8417752a1762c6ea4e3`. The PRD/ARD authority bundle may reach `ALIVE` through independent cross-repository verification; that standing does not promote the runtime, repository, production, security, certification, device, or ecosystem crown.

## Product Thesis

ggen transforms admitted observations into deterministic software artifacts and bounded intents: `A = μ(O*)`. The product is a proof-carrying capability distribution, not merely generated source.

## Repository Role

`ggen` owns generalized semantic admission, candidate construction, pack composition, deterministic manufacture and bounded intent production. `ggen-legacy` owns the executable architecture corpus, historical lineage, equivalence portfolios and independent receiver verification. BRCE is the only consequential actuation boundary.

## Customer Outcomes

Customers receive exact-source observations, admitted authority, dependency-closed plans, deterministic packs, capability passports, generated artifacts, bounded intents, receipt chains, replay and independently computed standing.

## Nonfunctional Requirements

Determinism, least privilege, outbound deny, portable dependency closure, immutable evidence, stage-level observability, checkpoint recovery and environment-bound performance evidence are mandatory. Machine-local absolute paths and undeclared sibling dependencies are release-critical refusals.

## Exclusions

v26.8.3 does not claim unrestricted program equivalence, recovered human intent, direct autonomous production mutation, physical-device proof without a device, certification, regulatory compliance, or a 1000x multiplier without admitted measured evidence.

## Launch Theorem

The authority bundle launches only when exact source identity, document digests, requirement traceability, component ownership, verifier assignment, zero self-certification cycles, zero direct-actuation paths, zero replay differences and peer-independent verification all close. Runtime Release Admission remains separate.
