# 29. Roadmap Principles

The roadmap must obey Gall's Law. The target is a complex executable enterprise architecture capability, so it must be grown from useful smaller systems.

Five principles govern sequencing.

## Architecture Before Inventory

Define the metamodel and authority rules before importing every repository. Otherwise the repository becomes an ungoverned data lake.

## Identity Before Automation

Establish canonical identity for ontologies, packs, capabilities, products, and receipts before generating cross-system consequences.

## Observation Before Prediction

Measure real ontology, pack, and workflow envelopes before issuing capacity warnings.

## Construction Before Actuation

Manufacture plans, artifacts, and intents before connecting broad execution authority.

## Standing Before Scale

Promote a capability only after positive, negative, adversarial, and replay evidence exists.

Each checkpoint must provide a useful developer or architecture outcome. The roadmap should avoid infrastructure that has no consumer.

The roadmap is divided into five waves:

1. Constitution and metamodel.
2. Repository and identity.
3. Lifecycle, contracts, and impact.
4. Transition, governance, and operations.
5. Self-hosting and ecosystem closure.

The crown checkpoint is not "all features implemented." It is a traversable proof that a proposed change can be followed from strategy through consequence and evidence.
