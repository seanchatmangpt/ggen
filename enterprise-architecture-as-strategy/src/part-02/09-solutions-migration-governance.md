# 9. Solutions, Migration, Governance, and Change

Phases E through H turn architecture from target description into controlled movement.

## Opportunities and Solutions

Phase E assembles candidate solution building blocks. In the Chatman Ecosystem, this is where Combinatorial Maximalism and CMD operate. The goal is not to choose the first plausible implementation. It is to construct a bounded candidate lattice and eliminate unlawful or dominated options.

Candidates may vary by:

- storage;
- deployment model;
- ontology profile;
- planner;
- validation depth;
- cache strategy;
- language;
- consumer contract;
- migration pattern;
- operating environment.

## Migration Planning

Phase F converts the selected candidate into transition architectures and work packages. MFW, POWL, and PDDL express dependencies, partial orders, resources, goals, and recovery paths.

A transition architecture must be independently valuable. Gall's Law applies: a complex target cannot be installed as one indivisible leap. Each checkpoint must operate as a useful system with evidence.

## Implementation Governance

Phase G evaluates conformance between the architecture contract and implementation evidence. Gall establishes standing. BRCE governs whether derived intents may actuate. The architecture board remains responsible for risk acceptance and exceptions that cannot be delegated.

## Architecture Change Management

Phase H consumes runtime observation. wasm4pm, OCEL, telemetry, capacity receipts, incident evidence, and consumer feedback reveal whether the operating system still corresponds to the target architecture.

Change management should detect:

- drift;
- unplanned dependencies;
- deprecated consumption;
- performance regression;
- policy violation;
- failed assumptions;
- unused platforms;
- replacement readiness;
- retirement opportunities.

The cycle closes when observed consequence becomes new admitted observation.

The executable ADM is therefore not a waterfall. It is a controlled feedback loop with persistent lineage:

```text
vision
-> architecture
-> candidate solutions
-> transition
-> implementation
-> operation
-> observed evidence
-> revised architecture
```

The architecture remains alive because its claims can be disproved by the enterprise it helped create.
