# 6. Preliminary Phase and Architecture Vision

The Preliminary Phase establishes the architecture capability itself. In many organizations, this work is treated as setup: choose a framework, define templates, identify a board, and publish principles. In an executable architecture system, the Preliminary Phase is constitutional engineering.

It must define:

- the enterprise boundary;
- architecture roles and decision rights;
- the architecture metamodel;
- standing vocabulary;
- approved standards;
- exception policy;
- evidence policy;
- lifecycle states;
- actuation boundaries;
- repository ownership.

The output is not merely a charter. It is the law under which later architecture objects gain authority.

A principle such as "zero unreceipted actuation" should be represented as a machine-visible invariant with an enforcement path and a falsifier. A principle such as "public ontologies are preferred" should identify approved vocabularies, conditions for local extensions, and review obligations.

Phase A then creates the Architecture Vision. Its primary object is an `ArchitectureInitiative` linked to:

- sponsoring outcome;
- stakeholders;
- affected capabilities;
- baseline concerns;
- target claims;
- scope boundaries;
- value measures;
- risk;
- required decisions;
- expected transition states.

The vision must not claim implementation. It authorizes investigation and defines the claim ceiling.

For example, a vision for global customer unification may establish that one customer identity is strategically required, but the vision should not predetermine whether the solution is centralized, federated, event-driven, or virtualized. Those are candidate solution questions for later phases.

The executable vision generates an initial burden of proof:

- current fragmentation must be observed;
- consumer requirements must be acquired;
- regulatory constraints must be admitted;
- candidate operating models must be compared;
- migration feasibility must be tested;
- capacity and cost envelopes must be defined.

This converts enthusiasm into bounded work.

A strong Phase A artifact therefore contains both ambition and refusal. It states what the initiative intends to make true and what evidence would force the architecture to narrow, delay, or abandon that claim.
