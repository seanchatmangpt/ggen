# How to Read This Book

This book can be read in three ways.

## Executive path

Read Parts I, II, VI, VII, and the synthetic case studies. This path explains why executable architecture changes the relationship between strategy, operating model, portfolio, and delivery.

## Architecture path

Read Parts II through V in order. This path develops the metamodel, the TOGAF mapping, the Enterprise Continuum, architecture contracts, lifecycle states, and combinatorial projection model.

## Implementation path

Begin with the Chatman Ecosystem in Part III, continue through the architecture repository and lifecycle chapters, then follow the roadmap. This path identifies concrete system responsibilities and Gall checkpoints.

Throughout the book, several standing words are used precisely:

- **ALIVE** means the stated capability has a positive witness and the required verification has passed.
- **PARTIAL_ALIVE** means a bounded subset has standing while the broader claim remains open.
- **BLOCKED** means a known external dependency prevents progress.
- **BUILD_BROKEN** means the implementation cannot currently pass its declared build boundary.
- **UNKNOWN** means the evidence has not been acquired.
- **UNSUPPORTED** means the current system does not provide the capability.
- **REFUSED** means an explicit law rejected an attempted transition.

These states are not project-management labels. They are epistemic and operational claims.

The chapters also distinguish four objects that conventional architecture frequently collapses:

1. **Architecture Building Block** - the capability or constraint that must exist.
2. **Solution Building Block** - a concrete implementation of that architecture.
3. **Artifact** - a material projection such as code, policy, schema, or document.
4. **Standing** - the evidence-backed status of a claim about those objects.

The synthetic cases are fictional. They are designed as adversarial architecture laboratories. Their purpose is to test whether the framework can handle complex operating models, regulated data, heterogeneous technology, cross-boundary packs, migration, capacity, and retirement without relying on a privileged narrative shortcut.
