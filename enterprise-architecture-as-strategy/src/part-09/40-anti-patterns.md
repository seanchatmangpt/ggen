# 40. Failure Modes and Anti-Patterns

## The Architecture Data Lake

Everything is imported before identity, ownership, and lifecycle are established. The graph becomes large but cannot govern consequence.

## The Universal Ontology

One ontology attempts to describe every domain and receives ambient authority. Local variation becomes either impossible or hidden.

## Diagram Authority

A stakeholder view is treated as the source of truth. Changes in implementation or runtime do not update it.

## Generated Evidence

The same transformation generates implementation and expected values. The tests prove only that generation is self-consistent.

## Planner Actuation

A planner directly executes actions. Candidate reasoning and authority collapse into one privileged component.

## Eternal Compatibility

No semantic asset is retired. Every version remains loaded, increasing ambiguity, cost, and attack surface.

## Marketplace as File Store

Packs are ranked by downloads or template count without contracts, proof, capacity, support, or lifecycle.

## Green Summary Collapse

Multiple standing dimensions are reduced to one status. UNKNOWN and PARTIAL_ALIVE disappear behind a reassuring label.

## Framework Theatre

TOGAF terms are added to documents without changing architecture decisions, delivery, or evidence.

## Combinatorial Explosion

Maximalism is interpreted as generating everything. Utility, ownership, validation, and capacity are ignored.

## Hidden Consumer Repair

A pack appears successful because expert consumers manually patch outputs. The handler gap is not measured.

Each anti-pattern is a failure of boundary definition. The remedy is usually not more automation but clearer identity, lifecycle, evidence, and authority.
