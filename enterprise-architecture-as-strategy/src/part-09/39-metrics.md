# 39. Metrics for Executable Enterprise Architecture

The architecture must measure whether it creates strategic leverage.

## Ontological Leverage Ratio

$$
OLR =
\frac{validated\ consequences}
{independently\ asserted\ facts}
$$

## Restatement Elimination

$$
RE =
1 -
\frac{manual\ semantic\ restatements}
{total\ semantic\ uses}
$$

## Traceability Coverage

$$
TC =
\frac{material\ artifacts\ linked\ to\ capability\ and\ requirement}
{all\ material\ artifacts}
$$

## Evidence Coverage

$$
EC =
\frac{claims\ with\ current\ receipts}
{claims\ requiring\ evidence}
$$

## Transition Closure

$$
TCl =
\frac{work\ packages\ with\ dependencies,\ rollback,\ and\ acceptance}
{all\ transition\ work\ packages}
$$

## Consumer Burden

Measure setup time, local code required, hidden assumptions discovered, and migration effort.

## Drift Half-Life

Measure the time between architecture drift occurring and the architecture repository reflecting it.

## Refusal Quality

Measure whether refusals name the violated law, affected object, evidence, and remediation.

## Capacity Prediction Error

Compare predicted and observed latency, memory, and throughput.

Metrics must resist gaming. Generated file count is not leverage. Number of ontology terms is not semantic quality. Passing tests generated from the same source values is not independent proof. Number of receipts is not evidence if receipts do not bind observations.

The portfolio should optimize for validated consequence, reduced maintenance, faster lawful transition, lower drift, and stronger replay.
