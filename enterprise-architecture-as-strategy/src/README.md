# Enterprise Architecture as Strategy with ggen

## From architecture description to lawful enterprise manufacture

Enterprise architecture has traditionally promised alignment between strategy and execution. The promise is correct, but the mechanism has been weak. Strategy is translated into diagrams, standards, roadmaps, portfolios, tickets, repositories, deployment manifests, policies, dashboards, and operating procedures. Each translation creates an opportunity for meaning to drift.

ggen changes the unit of architecture from a collection of documents to a governed body of admitted knowledge.

In this book, enterprise architecture is treated as an executable system of meaning. Capabilities, value streams, products, ontologies, applications, technologies, requirements, policies, transition states, evidence, and authority are represented in a canonical architecture graph. ggen projects that graph into the artifact families needed to build, govern, operate, verify, migrate, and retire digital systems.

The governing sequence is:

```text
observe
-> admit
-> model
-> derive
-> explore
-> plan
-> manufacture
-> verify
-> authorize
-> actuate
-> observe consequence
-> receipt
-> replay
-> evolve
```

This is not a claim that templates replace judgment. It is a claim that once an architectural judgment has been made and admitted, the organization should not repeatedly restate it by hand across every downstream surface.

The book combines three lenses:

1. **TOGAF** supplies the architecture-development and governance frame.
2. **Enterprise Architecture as Strategy** supplies the operating-model and execution-foundation frame.
3. **The Chatman Ecosystem** supplies an executable manufacturing, planning, proof, actuation, process-evidence, and release architecture.

The result is an architecture practice that can calculate impact before change, generate implementation and proof together, preserve authority boundaries, and observe whether the implemented enterprise still corresponds to the strategy that authorized it.

This book is a target architecture and a construction manual. Every chapter distinguishes:

- the architectural claim;
- the executable mechanism;
- the evidence required for standing;
- the refusal boundary;
- the next transition.

The final objective is not an enterprise diagram. It is an enterprise capable of explaining, manufacturing, and proving its own change.
