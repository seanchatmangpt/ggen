# ggen v2030.1.1 — PRD / ARD

**Repository:** `seanchatmangpt/ggen`  
**Ecosystem role:** manufacture / universal projection engine  
**Release:** Chatman Ecosystem v2030.1.1  
**Standing conferred:** `UNKNOWN`.

## Product requirement

`ggen` SHALL be the deterministic manufacturing engine that projects admitted semantic knowledge into implementation artifacts. Its v2030.1.1 objective is to make software construction a reproducible graph transformation rather than a collection of manually synchronized files.

Canonical law:

```text
admitted graph -> query -> generation plan -> template/renderer -> artifact graph
```

The product target is **one semantic admission -> zero manual synchronization** for ggen-owned surfaces.

## Required capabilities

1. Consume exact admitted graph/config identities and reject missing or incompatible inputs.
2. Support deterministic SPARQL/query-driven selection with stable ordering.
3. Manufacture multiple artifact families: source, schemas, APIs, CLI, MCP, A2A, policy, tests, docs, deployment, marketplace, observability, and formal-spec projections where packs define them.
4. Emit an artifact inventory binding input graph, query, template, generator version, parameters, path, and content identity.
5. Detect manual drift of ggen-owned projections.
6. Support idempotent regeneration and byte/semantic equivalence checks.
7. Preserve typed refusal and unsupported semantics across projections.
8. Provide reverse diagnostics from projection failure back to graph/query/template coordinates where possible.
9. Keep generated artifact construction separate from admission, proof, runtime execution, and authority.

## Architecture requirements

```text
O* semantic capsule
    -> query plan
    -> deterministic selection
    -> ggen render
    -> artifact DAG
    -> target-specific verifier
    -> receipt / replay
```

`ggen` may CONSTRUCT. It SHALL NOT infer that rendered code is correct, formally admitted, deployed, or authorized to execute. The repo law remains: generation is not standing.

The engine SHALL support DfCM by allowing many lawful projections from one canonical graph before consumers make irreversible target selections.

## Acceptance for v2030.1.1

- two runs over identical admitted inputs produce equivalent artifact inventories and content identities;
- unordered graph iteration cannot alter deterministic output;
- source-to-artifact provenance is queryable for every committed ggen-owned projection;
- hand-edited drift is mechanically detected;
- at least representative CLI/API/MCP/A2A/infrastructure/marketplace/formal projections are manufacturable from semantic packs without separate hand-maintained models;
- a failed target verifier cannot be converted into generator success standing;
- receipts identify the exact graph, generator, query, template, configuration, and outputs.

## Falsifiers

The architecture is falsified if a required generated interface must be maintained independently of the canonical graph; if identical inputs yield materially different outputs without an admitted nondeterminism contract; if a generated file cannot be traced to its source query/template; or if rendering grants implicit execution authority.

## Ecosystem contract

`ggen` manufactures projections. `open-ontologies` supplies shared meaning; `ggen-marketplace` supplies reusable executable knowledge packs; target systems admit behavior; Lean may admit formal projections; `mfact` certifies; BRCE-governed runtimes actuate. **ggen renders; it does not crown.**
